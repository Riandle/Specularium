已有的文件不用手抄。Word 可以通过仓库里的转换脚本一次性转成 Markdown，PDF 则作为附件挂到页面上。

## 先说结论

| 文件类型 | 处理方式 | 效果 |
| --- | --- | --- |
| `.docx` | 脚本自动转换 | 标题、段落、加粗、列表、表格、图片都保留，可在后台继续编辑 |
| `.pdf` | 作为附件上传 | 页面提供下载/预览链接，正文另写摘要 |
| `.doc`（很老的格式） | 先用 Word 另存为 `.docx` | 同上 |

## 转换 Word 文档

在仓库根目录运行（需要 Node.js 20 以上）：

```bash
# 单个文件
npm run import:docs -- "D:\资料\社区公约.docx"

# 整个文件夹，一次全转
npm run import:docs -- "D:\资料\待导入"
```

脚本会：

1. 读取文档，把标题、正文、列表、表格转成 Markdown；
2. 把文档里的图片抽取到 `public/images/imported/`；
3. 在 `src/content/docs/documents/` 下生成同名 `.md` 文件，并写好标题、摘要等头部信息；
4. 打印转换结果和需要人工检查的地方。

转换完成后：

```bash
npm run build     # 本地先看一遍效果
npm run dev       # 或者起一个本地预览，边看边改
```

确认没问题后提交，线上会自动更新。之后这篇文档就可以像普通文档一样在后台修改。

## 转换后要人工看一眼的地方

自动转换能保证**内容不丢**，但排版会有一些粗糙的地方，建议逐项检查：

- **标题层级**：Word 里如果没用「标题 1/2/3」样式，转换后就不会有小标题，需要手动加 `##`。
- **表格**：复杂的合并单元格会被拆开，建议改成简单表格或改用列表。
- **图片**：浮动图片、文字环绕图片的版式会失效，统一变成独占一行。
- **文本框 / SmartArt / 公式**：无法转换，会以「（图形/公式，请手动补充）」占位，需要手工处理。
- **页码、页眉页脚**：网页上不需要，会被丢弃。

## PDF 怎么办

PDF 是版式文件，不适合转成网页正文。推荐做法：

1. 把 PDF 放进 `public/files/`（比如 `public/files/2026-report.pdf`）；
2. 新建一篇文档，正文写摘要，末尾挂下载链接：

```markdown
完整内容见 PDF：[下载 2026 年度报告（2.1 MB）](/files/2026-report.pdf)
```

浏览器里点开会直接预览，移动端则提示下载，比强行塞进网页更稳。

## 批量导入的注意点

- 一次导入大量文件时，先在一个临时分支上做，确认构建通过再合并。
- 文件名建议先用英文或拼音，避免网址里出现一长串百分号编码；网页上的标题可以照旧用中文。
- 图片很多时注意仓库体积：单张压缩到 1 MB 以内，GitHub 单文件上限是 100 MB，但仓库越小构建越快。
