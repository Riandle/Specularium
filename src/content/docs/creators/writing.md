正文用的是 **Markdown**——纯文本加几个符号就能排版，后台有工具栏，也可以直接手写。

## 标题

用 `##` 开始二级标题，`###` 三级。**一篇文章只有一个标题**，就是后台里填的那个，
正文里不要再写一级标题（`#`）。

```markdown
## 二级标题
### 三级标题
```

右侧目录会自动根据二级、三级标题生成。

## 强调与链接

```markdown
**加粗**、*斜体*、`行内代码`
[站内链接](/intro/)、[外部链接](https://example.com)
```

站内链接直接写路径，**以 `/` 开头**，例如 `/intro/`。

## 图片

在后台的正文编辑器里点「图片」按钮上传，文件会存进仓库的 `public/images/`，
正文里会自动插入 `![](/images/xxx.png)`。

图片建议：

- 宽度控制在 **1600 像素**以内，单张不要超过 1 MB。
- 截图用 PNG，照片用 JPG。
- 一定要填**替代文字**（`![替代文字](/images/x.png)`），读屏软件和图片加载失败时都要靠它。

## 提示框

需要让人一眼注意到的内容，用提示框：

```markdown
:::note
一般提示。
:::

:::tip
建议做法。
:::

:::caution
需要小心的地方。
:::

:::danger
可能造成损失的操作。
:::
```

## 表格与代码

```markdown
| 列一 | 列二 |
| --- | --- |
| 内容 | 内容 |
```

```markdown
​```python
print("代码块会高亮")
​```
```

## 几条写作约定

- 段落之间空一行，不要用两个空格强行换行。
- 中文标点用全角，中英文之间加一个空格：`用 GitHub 存文件`。
- 长文档用小标题切分，每节控制在三四屏以内。
- 写完在手机上打开看一眼，表格和图片最容易在窄屏出问题。
